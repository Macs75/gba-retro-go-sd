# Changelog

This file is a template for the single project created from this repo.
At project setup time you choose exactly one kind by setting `PROJECT_KIND`
to `core` or `homebrew` (you will only build/release that chosen kind).

Update the content for your project and keep the section heading matching
the pushed release tag (CI requirement).

This file follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
[Semantic Versioning](https://semver.org/spec/v2.0.0.html). Release tags must
match a section heading exactly (for example `v1.0.0`).

When you cut a release:

1. Move items from `[Unreleased]` into a new `## [vX.Y.Z] - YYYY-MM-DD` section.
2. Commit the changelog update.
3. Push the tag: `git tag vX.Y.Z && git push origin vX.Y.Z`

CI reads the matching section and uses it as the GitHub Release notes. Assets
attached to the release:

- `<binary>-<tag>.zip` — SD layout only (`cores/` + packed `.bin` and sidecar `.xip`)
- `<binary>-<tag>-debug.zip` — ELF + linker map (use `arm-none-eabi-addr2line` for crash PC/LR → function/line)

## [Unreleased]

### Added

- **Wing Commander: Prophecy's 3D runs natively** (src/hle/hle_wcp.cc,
  generated by tools/gba_hle_wcp_gen.py from the game's IWRAM code): its
  textured span drawer (76% of the game's instructions in its real-time 3D
  cutscene), the polygon edge walker's loop that calls it a line at a time
  (the call and the return native), the vertex transform and the
  projection. Checkpoints every 16 instructions and at every branch target
  and return site, each bounded by the wait states of the memory its
  registers address there. Exact: the device recording's checkpoints all
  match. Device, against before: the 3D cutscene 11.9 -> 59.7 fps, a ship
  cutscene 19.1 -> 37.8, a capital ship's explosion 14.9 -> 32.4, frames not
  drawn over the recording 2,177 -> 829. A 0x13E8-byte ITCM overlay (the
  window did not grow); the tile converter, the clipped edge walker and the
  visibility test decode too but do not fit.
- tools/gba_hle_armgen.py: the ARM-to-C decoder the game HLE generators
  share (data processing with flag liveness, multiplies, byte/halfword/word
  and block transfers, VRAM block stores, BL/BX within a routine,
  checkpoint cost bounds); tools/gba_hle_mgolf_gen.py uses it (output
  unchanged).
- **Mario Golf: Advance Tour's sound mixer runs natively** (src/hle/hle_mgolf.cc,
  generated by tools/gba_hle_mgolf_gen.py from the game's own ARM words).
  The game mixes with its own routine (not M4A), copied to IWRAM and
  rewritten as it plays: an interpolating loop whose 8 sample slots take one
  of three templates by pitch step, and an output stage (echo, 8-bit output)
  whose back branch takes one of two targets. Each entry checks which form
  is in IWRAM (and hashes its words once a frame). Whole passes run
  natively, 16 instructions at a time when the cycles left cover their worst
  case (no stop can fall among them, so no test per instruction); the rest
  of a pass, mid-pass entries, the third template (2-6% of entries) and the
  clipping path are interpreted. Host, from power-on and two save states:
  picture, sound and memory identical; interpreted instructions -22% (the
  field) to -35% (menus). Device, the field (with the rotated-layer change):
  game code 4.9-5.2M -> 4.0-4.4M cycles a frame, frames drawn 50% -> 92%
  (49-60 fps). An ITCM overlay of 0x1484 bytes (V-Rally 3's is larger: the
  window did not grow); its entry checks are RAM code behind everything.
- **M4A's reverb loop runs natively** (src/m4a/m4a_reverb.c): the driver's
  once-a-frame loop that folds the last buffer back into this one (15 ARM
  instructions a sample), found by its bytes in IWRAM when the mixer is,
  through the native-routine hook when no game HLE holds it; exact cycles
  and stopping points, in the flash (nothing in RAM or ITCM moved). Power-on
  census, on top of the mixer resume: 40 games -1% to -51% (Wings -51%, Wing
  Commander: Prophecy -45%, Silent Scope -44%, Pokemon Pinball: Ruby &
  Sapphire -43%, Klonoa -34%, Lilo & Stitch 2 -25%, Harvest Moon: FoMT
  -17%, Pokemon Sapphire -16%), none worse, hashes identical. Advance Wars'
  recording: a further -6.6% (median window).
- **The M4A native mixer resumes a block after an interrupt** instead of
  leaving the block's rest to the interpreter: it notes where it stopped
  (with the registers and flags) and, when the interrupt returns there,
  runs on from that instruction (every runner now has an entry at each
  instruction, tools/m4a_add_resume.py), if the registers and flags are as
  it left them. With a line or timer interrupt most blocks are interrupted:
  Advance Wars interpreted 17K mixer instructions a frame, now none. With
  the calling-loop skip, power-on census: GT Advance -68%, Final Fight One
  -66%, Dragon Quest Monsters: Caravan Heart -62%, Advance Wars 2 -43%,
  Advance Wars -36%, Mega Man Battle Network -28%, Zone of the Enders -28%,
  Lunar Legend -21%, 11 more -1 to -8%; none worse, hashes identical.
- **The generic wait-loop skip takes loops that call functions** (C code's
  `while (!flag) check_keys();`): the loop search steps over calls, and the
  proof covers the whole pass, callees included: the same registers, flags
  and mode, and no side effect but Thumb pushes into the 64 bytes below sp,
  which must come out of the pass as they went in. Stores to I/O and video
  now count as side effects too (they never mattered while no loop with a
  store could be armed). Power-on census, interpreted instructions a frame:
  Final Fight One -66%, Advance Wars 2 -43%, Advance Wars -35%, Super Monkey
  Ball Jr. -6.5%; the other 145 games the same and with identical hashes.
  Advance Wars' recording: -27% (median window), still exact.
- **WarioWare: Twisted! runs at full speed in its intro, menus and level
  intros** (it dropped to 14-30 fps):
  - its VBlank wait loop (which steps a random-number generator every pass)
    is skipped, exactly: the RNG, the stack word and the store count advance
    as the skipped passes would. Once a pass's cost is measured, the skip
    happens on the first arrival after each event.
  - its sound mixer (three IWRAM loops: resampling, summing, output) and
    its unrolled 32-bit division run natively from the ITCM window
    (`src/hle/hle_rzw.cc`, loaded only for this game, 4,980 bytes), with the
    interpreter's exact cycles and stopping points.
  Host, interpreted instructions a frame: story select 87.9K -> 49.7K,
  first level's intro 69.2K -> 46.6K; both recordings replay exactly.
- **Tilt controls for Yoshi's Universal Gravitation / Yoshi Topsy-Turvy**
  (the cart's accelerometer at 0x0E008000): the Time button toggles tilt
  mode (TILT badge); in it L and R tilt the world left and right, while the
  D-pad still moves Yoshi. A held button is a full tilt (the game only
  tells level, left and right apart). Playable, but the game is built for
  the real sensor and is hard to play on buttons.
- **Tilt controls for WarioWare: Twisted!** (gyro sensor on the cart's
  GPIO): the Time button toggles tilt mode; in it, D-pad left/right turn
  (ramping up while held). A small TILT badge in the bottom-left corner
  shows when tilt mode is on.
- **Record and replay input** from the pause menu ("Record input" /
  "Replay input"): the game restarts from power-on and the keys of every
  frame are saved next to the ROM (`<game>.rec`, with the cart save as it
  was at the start); a replay plays them back exactly, for reproducing a
  problem or comparing performance. A replay uses the recording's cart
  save, so the player's save file is not written for the rest of that
  session. Every 120 frames both log `REC/hash` lines (RAM, video, CPU and
  audio hashes): two runs of one recording must print the same lines. A
  replay or recording also ends with a `REC/hash` line for its last frame
  (unless that frame was just hashed), so the very end can be compared.
- **Generic poll-loop skip, for every game**: loops that only read and
  compare (waiting on DISPSTAT, VCOUNT or a RAM flag an interrupt sets) are
  found while the game runs, and their passes are skipped up to the next
  hardware event once two passes prove they change nothing (no store,
  identical registers and flags). Exact: host replays with and without it
  log the same `REC/hash` lines in all 149 games of a 150-game set that run
  on the host. Kirby & The Amazing Mirror: 12-17% fewer instructions in its
  heaviest stage-2 scenes. A wait loop that jumps over data (its literal
  pool between a branch and its target) is followed along its branches:
  Super Mario Advance's VBlank wait, which ran from the interpreter, is
  skipped (device: ARM 4.0-4.6M -> 1.8-3.5M cycles a frame, every frame
  shown; it dropped frames in 13 of 62 windows).

- Host: `GBA_SCREENHASH=N`, a hash of the drawn picture every N frames
  (`REC/hash` does not see the picture: for renderer changes);
  `tools/gba_callgrind_window.sh`, callgrind over frames A-B of a replay
  only; the video trace (`-DGBA_VIDEO_TRACE`) also keys the windows and the
  blend factors and counts the lines with semi-transparent sprites.
- Host tools: `GBA_PCHIST=1` (PC histogram, `tools/gba_pchist.py`),
  `tools/gba_idle_census.sh` (poll loops across a ROM set),
  `tools/gba_idle_ab.sh` (the skip against none, over a ROM set).
- `make PROF=1`: a profiling build that prints `PROF/` lines every 120 frames
  (frame budget, the ARM7 / renderer / M4A mixer split, scaling, the LCD and
  audio waits); with `PCS=1` it also samples the device CPU's PC at 1 kHz
  while a replay runs (the firmware's SysTick through a handler in ITCM): `<game>.pcs` next
  to the ROM, one histogram per 1800 replay frames, read with
  `tools/gba_pcs_report.py` and the build's ELF.
- Host: `GBA_WAV=<file>` (every sample the core produces, as a WAV, also
  unthrottled) and `GBA_DUMP=N:<file>` (EWRAM + IWRAM at frame N, read
  through the core), for comparing a game's sound and state with another
  emulator.
- Host: `GBA_CALLGRIND_FROM=N` (callgrind's counting starts at frame N,

- Host: `GBA_MONKEY=<seed>` (random buttons in the place of the keyboard,
  to get games through their menus without a recording;
  `GBA_MONKEY_START=<pct>` the Start presses after the first minute) and
  `GBA_OBJMAX=1` (the most distinct sprites one priority puts on one line);
  `tools/gba_objmax_census.sh` runs both over a ROM set, with each game's

- Host: `GBA_FAST=1`, `GBA_EXIT_FRAME=N`, `GBA_FRAMESKIP=N`, `GBA_RECORD=1` /

### Changed

- **The blended screens' unrotated rotate/scale layer draws from RAM**: the
  32-bit indexed-colour instances (wrapping, no mosaic) and their
  dispatchers left the flash, where their cost moved with gba.xip's place.
  Wing Commander: Prophecy's cockpit draws its 3D layer through them: -9.5%
  drawing per drawn frame there, 53 -> 58 fps. Behind the RAM code, after
  the late code, which now has a fixed 0x250-byte slot so what follows
  keeps its address.

- **Rotated layers draw a cell at a time.** A rotated, unmosaiced layer
  (modes 1 and 2) now computes once per line which of its pixels fall on
  the map (exactly, in integers: no bounds test per pixel), and walks them
  reading the map once per 8x8 cell it enters (affine_rot_run, its
  constants in one struct so the walk's values stay in registers: 18
  instructions a pixel inside a cell against ~26 and four stack accesses).
  Every frame identical on Mario Kart, F-Zero, WarioWare: Twisted! and from
  Mario Golf: Advance Tour and Mario & Luigi save states. Device, Mario
  Golf's field (two rotated layers, 92% of pixels in the previous pixel's
  cell): drawing -27% per drawn frame (1.90M -> 1.39M cycles), frames drawn
  38% -> 50%. The walks are RAM code next to the renderers; the code now
  ends past .bss's pin, so .bss starts 4 KB later (same place mod 4 KB):
  4 KB less RAM after the core.

- **The GBA's real frame rate, 59.7275 Hz** (280,896 cycles of 16.78 MHz).
  Every sample a frame produces (803.65 on average at 48 kHz) goes into the
  firmware's interrupt-fed audio ring, and the loop paces on that ring, so
  it runs at the audio's rate divided by the samples per frame: the GBA's.
  The LCD refresh is set to the same rate (milli-Hz, read back from the
  real audio clock; firmwares without milli-Hz rates keep 60 Hz), and the
  firmware's frameskip gets the exact frame time.
- Every frame that is on time, or late with at least 2 frames of audio
  still queued, draws at a fixed point of the LCD's scan (after the last
  swap has shown, between scan lines 32 and 200), so its swap never
  straddles the vertical blank; a late frame with the audio low draws at
  once, or drops its picture if the last swap has not shown yet.
- **Smoother FULL / FIT scaling** (the "hard" filter): the arcade core's
  scaler. Every 3 GBA pixels make 4 on the panel, (s0, s1, avg(s1,s2), s2),
  and every panel row is a 2-tap blend of the two GBA rows around it, done
  by DMA2D from a small ring of pre-scaled rows while the CPU scales the
  next one. Scaling OFF and the "soft" filter are unchanged.
- Faster interpreter: the ARM7's flags are written into the CPSR only where
  something reads them (MSR, MRS, SWI, the M4A HLE, events, interrupts)
  instead of before every instruction, and the cheat hook shares the idle
  skip's one PC compare (with cheats on, the idle skip is off). Exact: the
  same `REC/hash` lines as before in all 149 games that run on the host.
- Interpreter: the special PCs (the idle skip's loop head, the M4A
  mixer's entry, the cheat hook) are tested only after an ARM jump or on
  entering the ARM loop, not before every ARM instruction, and the PC is
  masked only when it is misaligned.
- Interpreter: the PC is kept in a local copy. The handlers' PC offsets
  are stores from it instead of load-add-store sequences on `reg[15]`, and
  the fetch, region check and alignment read it instead of memory. Every write
  of the PC also updates the copy, so the dispatch never reads `reg[15]`
  (host `HOST_EXTRA_DEFS=-DGBA_PC_CHECK` checks it after every
  instruction). Device, Tony Hawk's Underground: -3.2% interpreter cycles,
  4,617 -> 4,926 pictures shown of 5,640.
- Interpreter: ARM conditions by a 16-entry table with an AL fast path (no
  16-way jump per instruction); stores to work RAM done by small functions
  in ITCM (no call into `write_memory*` in AXI RAM); LDM/STM visit only the
  listed registers; Thumb's idle-target compare uses a local copy. Device,
  Tony Hawk's Underground: -8.4% interpreter cycles, 4,926 -> 5,200
  pictures shown of 5,640, windows at a full 59.7 fps 15 -> 29 of 47.
- Interpreter code size: power-on and savestate code moved from ITCM to the
  XIP flash with the rest of the cold code. The register-operand barrel shifter and
  the shifted register offset of LDR/STR are one shared copy each instead
  of being expanded in every ALU and load/store case; the shifts by an
  immediate, nearly all real code, stay inline. LDM/STM share one body: the
  forms compilers emit (push/pop, LDMIA/STMIA, LDMDB, all Thumb forms)
  inline it, the 26 other ARM forms call one copy. ITCM free: 840 B ->
  12.6 KB. Device, Tony Hawk's Underground: interpreter cost unchanged,
  5,200 -> 5,264 pictures shown of 5,640, frames over budget 2,359 -> 1,981.
- Interpreter: the cycle count and the four flags stay in registers (no
  local's address escapes any more), and Thumb uses threaded dispatch:
  every handler ends with its own fetch and jump through a label table in
  ITCM; an alert is folded into the cycle count instead of being tested
  after every Thumb instruction. Device, Tony Hawk's Underground: -3%
  interpreter cycles.
- Hot code out of the flash: the plain sprite renderer, the tile-layer
  drivers, the M4A HLE's memory helpers and the idle skip's hooks run from
  ITCM (the device PC sampler found them running from gba.xip); the serial
  port is no longer polled at every event while no link device is
  emulated.
- Renderer: the text layers' tile loops are unrolled (8 pixels a tile as
  fixed bit-field extracts, no loop counter or variable shift) for the
  16-bit full-colour instances, the plain layers of nearly every game, and
  the 32-bit indexed/stacked ones, which every screen with blending or a
  brightness fade draws through (31% of the text pixels in the first
  minute of a 150-game set). Same pictures, frame by frame, in 10 games.
  Device: Tony Hawk's Underground drawing -20%, Kirby & The Amazing Mirror
  -13%; Tony's blended menu a further -12% per drawn frame.
- The blended screens' sprite renderers and the window/effects driver run
  from RAM instead of the flash: -12 to -17% drawing per drawn frame in
  Tony Hawk's blended menu, 3 of its 5 windows no longer skip frames. The
  room came from moving the load-time and savestate code (game load,
  memory setup, the memory/sound/main savestate parts) to the flash.
- Code and data placement is pinned where the device measured it best:
  the code after the interpreter in ITCM (mod 32), the hot RAM drawing code
  (mod 8 KB, the I-cache's set span), the flash read-only data and the GBA
  memories (mod 4 KB, the D-cache's set span). Unpinned, unrelated edits
  moved the drawing's cost by 5-14%.
- The game's M4A sound mixer (the native one, run per sound buffer) is
  copied from the flash to the AHB heap at start-up and runs there: the
  flash blob's place is the firmware's (4 KB aligned, a new one at every
  update), so the same mixer's cost depended on where it landed (Kirby & The
  Amazing Mirror: 524-763K cycles a frame). Its calls into the ITCM memory
  helpers are direct (-mlong-calls) instead of through veneers in the flash.
  Device, Kirby: mixer -24.5%, emulation -3.8%, same state hashes. If the
  AHB heap has no room the mixer stays in the flash (the log says which).
- Interpreter: the ARM loop no longer tests for an alert (a halt, an
  interrupt) after every instruction: raising one biases the cycle count, as
  in Thumb. The rare LDR/STR forms (none above 0.05% of any game's ARM
  instructions in a 150-game set) run out of line; LDM/STM, PUSH/POP within
  one page of work RAM or a mapped region copy the registers directly; cpu.o
  is built with -fno-tree-pre -fira-region=one, which keeps its register
  allocation from flipping (ITCM free 1.1 -> 7.6 KB). Device: Tony Hawk's
  Underground gameplay -2.9% interpreter; Thumb-heavy code +1.5-3% (Kirby,
  Tony's menus). Same state hashes in 146 of 150 games (the other 4 as
  before).
- Interpreter: ARM load/store offsets shifted right (LSR/ASR #n), as texture
  mappers index, run inline like LSL #n instead of through a call: V-Rally 3's
  race -2% interpreter.
- The rotated/scaled background renderers (modes 1 and 2: the plain-colour
  set and the blended layers' instances) run from RAM instead of the flash.
  Device, F-Zero: Maximum Velocity's race: drawing -5.1% per drawn frame,
  frames skipped 246 -> 157.
- Windows 0/1: when a line's window regions show the same layers and differ
  only in the colour effect (a game dimming part of the screen), the layers
  are drawn once and each region merged with or without the effect; they
  were drawn again per region, five times a line with two side-by-side
  windows. Same pictures (host picture hashes, all 4693 frames of the
  recording). Device, Super Puzzle Fighter II's match: drawing 2.36M ->
  1.99M cycles per drawn frame, 33-47 -> 39-48 frames shown a second.
- Game HLE: a game whose frame is dominated by one guest routine can have it
  run natively, with the interpreter's exact memory accesses, cycle charges
  and stopping points (same state hashes). Each routine is an overlay linked
  to an ITCM window, stored in gba.xip and copied there only when its game
  loads (`src/hle/`). First: V-Rally 3's textured-polygon rasterizer, 40% of
  its race. Device, the race: emulation 7.09M -> 5.3M cycles a frame (90% of
  the budget), 15 -> 53 frames shown a second. Second: Super Puzzle Fighter
  II's sound mixing loops (Capcom's own driver, which the M4A HLE does not
  see), a third of its match's instructions: device, the match's game code
  5.1M -> 4.1M cycles a frame, 16 -> 36 frames shown a second.
- `PROF/` lines: `fps`, dropped pictures (`vskip`), late frames, the audio
  ring's lowest fill, `PROF/idle` (the generic skip), and with `CPI=1`
  `PROF/cpi` (device cycles per GBA instruction; the count itself costs the
  interpreter 7-9%, so it is opt-in).
- `make PCS_BLOCK=N` (with `PCS=1`): one PC-sampler histogram every N replay
  frames (default 1800; 120 gives one per `PROF/` window). A PROF build
  without the sampler keeps the sampler build's code and data placement
  (its room kept as padding), so the two compare directly.

- **The cart save takes 64 KB of RAM instead of 128 KB.** A 1 Mbit flash
  save (Pokémon) keeps one 64 KB bank in RAM; the other bank's sectors are
  read and written to `<rom>.gba.sram.bank0` / `.bank1` next to the save,
  one 4 KB sector at a time and only when the game switches banks (no long
  pause). The save file itself is unchanged (the full 128 KB image), and
  so are recordings. Device, Pokémon Ruby: in-game saves, reloads and a new
  game's save over the old one all correct. Frees 64 KB of the core's RAM.
- Renderer: the darken/brighten effects (a fade, a dimmed screen) are one
  table load per pixel: a 1,024-entry table per BLDY value follows the
  palette writes (rebuilt within a budget of 2,048 entries a frame, else
  computed per pixel as before). A line with windows plans its regions once
  per window setting and draws each layer once over all of them, and the
  window code runs from RAM. Device, Super Puzzle Fighter II's match:
  drawing -14 to -23% per drawn frame.
- Renderer: a game that rewrites its sprite table during the frame (a
  sprite multiplexer) has its sprite lists built 16 lines at a time, not
  down to the bottom at every rewrite (each line's list depends on that
  line only: the same lists). Super Puzzle Fighter II's full board: half
  the list writes, drawing -3.5%, 45.6 -> 47.0 frames shown a second.
- The 16-bit sprite renderers for indexed colour and sprite windows, every
  bitmap-mode renderer (modes 3-5) and the window drivers run from RAM, not
  the flash: from the flash their cost changed with where gba.xip landed at
  each update (Super Puzzle Fighter II's early match +15-20% drawing,
  V-Rally 3's race +24%, with no renderer change). Device, V-Rally 3's
  race: drawing 1.51M -> 1.16M cycles per drawn frame, 1,940 -> 1,040
  frames not drawn over the replay.
- Interpreter: a Thumb instruction that leaves the PC on the next one
  tests the page first and charges the fetch from that page's wait-state
  row, without the poll-loop head test (a loop head is reached by its
  branch): ~8 fewer instructions each. Device: game code -4.5% in Super
  Puzzle Fighter II, -5.3% in Kirby & The Amazing Mirror (peak 82 -> 78% of
  the frame budget).
- Super Puzzle Fighter II: its line interrupt (183 a frame, a sprite
  multiplexer that works on 3-6 of them) runs natively on the lines where
  its handler only compares and returns -- the BIOS entry, the game's
  dispatcher and handler, ~25% of the match's instructions -- with the
  interpreter's exact state; a slice that ends inside it resumes there.
  Device, the full board: 40 -> 45 frames shown a second with the Thumb
  change above.
- The generic poll-loop search runs from RAM and ignores PCs inside a game
  HLE's routine; the scaler's row lane runs from ITCM.
- `PROF/` windows restart when a replay or recording starts, so two runs of
  one recording pair window by window.

- The per-game idle tables (gpSP's `gba_over.h`, `gba_idle_loop.c` and the
  two hand-listed VCOUNT polls) are off: on 37 of the 47 games of the set
  they covered, the generic skip removed 39-88% more instructions (and as
  many on the other 10), exactly, where the tables' skip was not.
  `make GBA_IDLE_TABLES=1` brings them back instead.

### Fixed

- **Sprites beyond 32 on one priority on one line were not drawn.** The
  sprite lists were cut from gpSP's 128 per priority per line (100 KB) to
  32 to fit the RAM, and a line that asked for more dropped the rest: Donald
  Duck's forehead in a Kingdom Hearts: Chain of Memories dialog went missing
  once the text was written. A census (`tools/gba_objmax_census.sh`, 149
  games, random input; and the recordings) found 23 games past 32 and 5 past
  48: Spyro: Season of Ice 73, Bruce Lee: Return of the Legend 57, Rayman
  Advance 56, Kingdom Hearts: Chain of Memories 52, Yggdra Union 51; then
  Yoshi's Island 48, Mega Man Zero 2 and FF Tactics Advance 46, Tony Hawk's
  Pro Skater 3 44, FF V Advance 43, Super Puzzle Fighter II 35. No fixed
  bound below the hardware's fits the RAM. Now each line keeps a chain per
  priority, in drawing order: order_obj pushes each sprite on the front of
  its priority's chain (a load and two stores per sprite and line, as the
  capped lists cost, without the bound; the per-line OBJ cycle budget still
  applies, as on the hardware), and a renderer follows its priority's chain
  only. Nothing sorts, in the RAM the old lists used. (A single list a line
  sorted by priority at each build cost Super Puzzle Fighter II, which
  rebuilds its lists ~20 times a frame, +2.0% drawing; walking a line's
  whole list per priority, +1.7%.) Device against the capped lists: Kirby &
  The Amazing Mirror +0.07% drawing per drawn frame, frames not drawn
  unchanged; Super Puzzle Fighter II median window 0.0%, +0.43% over the
  replay, frames not drawn 309 -> 332 (two windows whose skips shifted).
  Every frame identical where no line went past 32.
- **WarioWare, Inc.: Mega Microgame$! froze at Jimmy's disco stage**
  (device only): the OBJ window renders its inside into the line below as
  scratch, so the last line needs a line 160; the 160-line framebuffer had
  none, and that scratch overwrote the BIOS copy allocated right behind it
  in DTCM (its interrupt return), sending the game into the BIOS reset path
  at the next interrupt. Only on drawn frames, so it came and went with frame
  skipping. The framebuffer now has the spare line (480 bytes).
- **WarioWare: Twisted! locked up in Jimmy's third stage**: IME (the
  interrupt master enable) is one bit on the hardware, but any non-zero
  value enabled interrupts here. The game turns them off with 0xF200 (bit 0
  clear) and kept taking them, into a reset loop.
- **Sampled music played random notes in games that ask the BIOS for a
  note's playback rate** (WarioWare: Twisted!): the bundled open BIOS had
  nine addresses linked for the cartridge (0x0800xxxx) instead of itself, so
  `MidiKey2Freq` (SWI 0x1F) read its pitch table from the game's ROM. They
  are rebased in `src/gpsp/bios/open_gba_bios.bin` (found by comparing RAM
  and a CPU trace with mGBA). A real BIOS in `/bios/gba/` was never affected.
  The BIOS objects now rebuild when the image changes.
- Games without the M4A sound driver spent ~2M cycles a frame (a third of
  the frame) for their first 600 frames on the search for its mixer: a
  memcmp per variant at each of 8,192 IWRAM offsets. An offset now gets the
  full compare only when its first word matches (all variants share it):
  same result. Device, Tony Hawk's Underground: 200 -> 0 frames skipped in
  the first 10 seconds.
- The generic poll-loop skip lost real poll loops that shared a 64-byte
  block with rejected code: rejected loops are now remembered by their head,
  and a rejected block is decoded again at every 16th event pair. 18 of the
  150 host games had lost most of their skip (Broken Sword ran 73K
  interpreted instructions a frame instead of 12K).
- Pacing: the loop locked onto the LCD (60 Hz set, ~59.64 Hz real) because
  drawing slept until the last swap showed; it then never waited for the
  audio, which slowly underran, and the frameskip's rounded frame time
  (16.74 ms against 16.77 real) skipped 2 frames every ~10 s on frames with
  10-16% to spare (Kirby & The Amazing Mirror).
- Build: the -O2/-O3 objects (CPU, memory, renderer, sound, BIOS and M4A
  HLE) got no dependency files, so a header change did not rebuild them,
  and a stray `-DUSE_HAL_DRIVER` file appeared in the tree.
- Host build: a missing `odroid_system_switch_app` and a `frame_counter`
  clash with gpSP's own.

## [v0.0.1] - 2026-08-20

### Added

- Ported the firmware Game Boy Advance core (gpSP + `porting/gba` + M4A HLE)
  into this standalone tree: `/cores/gba.bin` + `/cores/gba.xip`, `ggcodes`
  cheats, optional `/bios/gba/gba_bios.bin`.
- Tag releases ship install + debug zips only (no loose `.bin`): SD layout
  includes `gba.xip`; debug zip has ELF/map for `addr2line` / `resolve_addr.py`.

### Changed

- Packed output is `gba.bin` (`/cores/gba.bin`). ROMs under `/roms/gba/`.
- ITCM holds hot **code only** (interpreter, M4A gpsp glue, `update_scanline`).
  No ITCM data.
- 240×160 framebuffer is `dtc_malloc`'d (75 KiB; leftover AHB is too small).
  BIOS and sound ring prefer DTCM, then AHB. Cheats stay on the AHB heap.
- Logos from firmware `icons/c_gba.bmp` + `h_gba.bmp`.

### Added

- Freestanding Cortex-M7 skeleton (`src/main.c`) with LCD demo, square-wave
  audio, save/load/screenshot hooks, and watchdog-friendly frame loop.
- Vendored SDK, linker scripts, and ABI bridge for `gw_firmware_abi_t`.
- Packaging for both project kinds:
  - **core** → `pack_core.py`, SD path `/cores/<name>.bin`
  - **homebrew** → `pack_homebrew.py`, SD path `/homebrews/<name>.bin`
- Docker builder integration (`make docker`) using `sylverb/retro-go-sd-builder`.
- CI build on push/PR and automated GitHub Release on `v*` tags.

### Install

Only the section corresponding to your chosen `PROJECT_KIND` is relevant for
your derived project.

**Core (`PROJECT_KIND=core`, default)**

- Copy `example.bin` to `/cores/` on the SD card.
- Place test ROMs under `/roms/example/` (dirname matches `CORE_NAME` in the
  Makefile).
- Requires firmware whose ABI matches `SDK_VERSION` in this repository.

**Homebrew (`PROJECT_KIND=homebrew`)**

- Set `PROJECT_KIND=homebrew` in the Makefile, rebuild, then copy
  `ExampleHB.bin` to `/homebrews/`.
- Optional coverflow override: `/covers/homebrew/ExampleHB.img` (JPEG ≤186×100,
  ≤10 KiB).

The release archive contains the ready-to-copy SD layout for the active project
kind only (`cores/` or `homebrews/`).
